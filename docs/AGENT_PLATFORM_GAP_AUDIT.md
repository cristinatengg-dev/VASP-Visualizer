# EliangMat AI 智能体平台差距审计

更新日期：2026-08-10

## 结论

项目已经具备“科研智能体产品原型 + 一部分生产运行时”的骨架，不是从零开始。前端已有连续科研流程、任务快照、文献/结构检索、建模、输入编译、人工确认、计算提交与 PPT 产物；后端已有 Session、Artifact、TaskRun、JobRun、Approval、Event、Skill 等运行时对象以及若干 worker/adapter。

距离完整平台的主要差距不在继续增加 Agent 卡片，而在于把目前并存的 demo/runtime、页面直连流程和真实后端能力收敛成一套可多租户运营、可观测、可审计、可扩展的生产控制面。

## P0：上线前必须完成

### 1. 收敛为单一生产运行时

本轮已完成任务级统一：工作区任务使用服务端 Session 和版本化 `workspace_snapshot` Artifact，具备乐观锁、事务写入、归档/软删除、身份隔离、持久卷和 Runtime 健康门禁。仍需把检索、建模、编译和汇报的实际执行从页面直连逐步迁入独立 worker。

- 移除产品路径对 `runtime-demo`、mock job 和 local demo 语义的依赖。
- 工作台的检索、建模、编译、审批、提交、采收与汇报全部通过同一 Runtime API 执行并持久化。
- 每个动作具备稳定的 correlation ID、幂等键、输入/输出 artifact、状态机和终止原因。

验收：服务器重启、前端刷新或 worker 故障后，任务可从持久化状态继续；同一请求重放不会重复提交计算。

### 2. 分布式任务与 Worker 控制面

- 引入可靠队列和独立 worker，不在 Web 进程里承担长任务。
- 增加租约、心跳、取消、超时、指数退避、死信队列、并发/资源限制。
- 对 GPU 图像、PDF、建模、HPC 采收等不同 workload 建立独立队列和隔离策略。

验收：worker 随机退出时任务不会丢失；失败原因、重试次数和恢复过程可在 UI 查看。

### 3. 多租户、权限与凭据安全

- 建立 Organization → Project → Workspace → Task 的资源层级。
- 上线 RBAC/ABAC、SSO/OIDC、服务账号、API token、邀请与成员生命周期。
- SSH、HPC、模型和商业数据库凭据进入加密 Secret Vault；前端不得接触明文。
- 对文件解析、Python/模型工具和用户脚本使用容器/沙箱隔离、网络策略和资源上限。

验收：跨租户读取在 API、数据库查询和对象存储三层都被阻断；所有密钥访问可审计。

### 4. 可观测、成本与质量闭环

- 每次 run 记录模型版本、prompt/skill 版本、工具调用、耗时、token、费用、缓存命中和错误分类。
- 建立材料检索准确性、结构构建成功率、输入文件有效率、作业收敛率、报告引用正确率等 eval。
- 部署前必须通过固定回放集和领域专家抽检门槛。

验收：能回答“哪个版本在什么数据上退化、影响了哪些任务、花了多少钱”。

### 5. 数据与合规治理

- 为论文、结构、商业手册、NASA/ESA 资料分别记录许可、访问方式、缓存期限、可再分发范围和引用格式。
- 上传文件需要恶意文件扫描、敏感信息/出口管制提示、删除与保留策略。
- 商业航天材料库中的工程预选值不能直接作为设计许用值；必须保留牌号、批次、厚度、热处理和工况限定。

验收：每条外部数据和派生产物都能追溯来源、许可和处理历史。

## P1：从可用产品到平台

### Agent 与 Skill 平台

- Agent/Skill 注册中心：schema、版本、依赖、权限、资源、owner、changelog。
- 可视化工作流编辑器：串行、并行、条件、循环、人工节点、子流程和模板发布。
- 模型路由：按任务质量、延迟、成本、上下文和数据策略选择模型；支持预算上限和降级策略。

### 团队协作与知识资产

- 项目级材料库、结构库、计算模板、实验方案和报告模板。
- Artifact diff、评论、审批、分享、引用、收藏和全文/语义检索。
- 团队任务交接、通知、定时运行、Webhook 和外部系统连接器。

### 商业化运营

- 套餐、额度、计量、发票、超额策略与成本归因。
- 管理后台、租户健康、滥用控制、支持工单、数据导出/删除。
- SLA、备份恢复、灾备演练和状态页。

## 当前最明显的工程风险

1. 产品内仍大量出现 `demo` / `mock` 路径，容易让 UI 表现和真实可恢复执行产生偏差。
2. 工作台任务主状态已迁到服务端，但快照文件仍使用单机持久卷；多副本前需要共享存储或对象存储与垃圾回收。
3. Session/Artifact/Event 已统一，检索、建模、编译和汇报的执行仍有页面直连路径，尚未完全收敛到独立 worker。
4. 自动化测试目前远低于平台复杂度，尤其缺少工作流状态机、审批、任务恢复、数据源契约与 Agent eval。
5. 真实 HPC、商业数据库和材料资格数据涉及高价值凭据与许可，需要先完成 Secret 与数据治理再扩大连接器。

## 推荐实施顺序（12–16 周）

1. 第 1–3 周：统一 Runtime API、状态机、幂等键和 artifact 契约；把工作台主链迁入。
2. 第 4–6 周：可靠队列、独立 worker、取消/重试/恢复、对象存储与全链路 trace。
3. 第 7–9 周：Organization/Project/RBAC、Secret Vault、沙箱和审计日志。
4. 第 10–12 周：Agent/Skill registry、版本与 eval 门禁、运营指标和成本计量。
5. 第 13–16 周：团队协作、工作流编辑器、连接器 SDK、计费与生产灾备。

## 本轮已经补齐的产品层

- 商业航天材料库从少量公式快捷入口扩展为按任务、材料族、成熟度和温度筛选的工程预选目录。
- 每个候选增加应用部位、优势、关键风险、资格验证项、TRL 与官方证据入口。
- 原子级材料仍可查询已连接结构源并送入 Modeling Agent；合金/复材明确提示需按真实牌号和工艺建模。
- 智能体首页增加生产流程模板、动态执行阶段、Agent registry、Workspace 状态和治理说明，保留原有连续科研执行链。
- 工作区任务从浏览器主存储迁到服务端 Runtime Session；本地存储只作为缓存和离线副本。
- 快照采用不可变 Artifact 版本链、`snapshotRevision` 冲突保护和原子文件写入；任务创建、事件、归档与软删除使用 MongoDB 事务。
- Compose 增加 MongoDB replica set、Runtime 持久卷、自动索引初始化与健康门禁；登录 owner 由签名 token 绑定。
