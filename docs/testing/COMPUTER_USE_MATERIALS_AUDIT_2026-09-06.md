## 结论

页面入口、持久保存与部分流程控制已可用，视觉方向可以保留。当前产品仍是研发流程与数据管理原型，不能判定为已经具备真实材料研发的完整智能体能力。

优先修复三项直接影响研究可靠性的问题：用户目标被默认值替代、结果达标判断忽略工况与质量状态、合金成分缺乏结构化校验。然后打通研究规划、任务执行、实验数据和下一轮设计。

本轮没有修改业务代码、发送短信、执行真实仿真/设备任务、真实支付或模型训练，也没有部署。通过 Computer Use 实际操作页面，创建了隔离的测试账号和明确标注为虚构的验收记录；没有用后台 API 代替业务操作。

## 优先级与复现结果

P1 表示会妨碍真实研发验收或属于核心能力缺口；P2 表示显著产品体验问题。这里区分已复现错误与尚未实现能力，不把开发版标注“待接通”视为已经完成集成。

### A01 · P1 · 已复现错误：目标没有可靠地进入研究计划

步骤：新建研究时填写“200°C、300 MPa、8%、4 周” → 打开「目标与约束」和「研究计划」。

实际：原文字保留，但结构化强度目标显示 **350 MPa**；任务名称为 **室温拉伸测试**。目标编辑只有强度、延伸率和样品上限，温度、周期没有独立字段。本轮为继续验收，手工把 350 改为 300；室温任务仍在。

影响：客户以为系统理解了需求，后续比较却可能使用默认值和错误工况。

修改：先形成需要确认的需求卡；性能名称、单位、阈值、温度/环境、标准、重复次数、预算和期限共用同一份版本化数据。缺失信息显示待补齐，不能悄悄填模板默认值；模板与目标冲突时阻止路线确认。

验收标准：这个输入在创建页、路线、实验表单、结果页一致显示 300 MPa / 200°C；不支持解析的条件必须提示用户确认。

### A02 · P1 · 已复现错误：达标提示忽略工况和质量状态

步骤：给目标 200°C 的项目录入 25°C、315 MPa、9% 的记录，测试条件中明确写“工况不一致” → 查看结果 → 复核选择暂不纳入。

实际：未复核时显示 **均值达到**；排除之后仍同时显示 **均值达到** 和 **暂不纳入**。下一轮按钮确实被禁止，但结论卡本身仍产生误导。

修改：把“数值高于阈值”与“满足研究目标”分开。只有质量可用、工况可比、指标定义一致的结果才能参与达标判定；待复核、已排除、缺失条件分别显示对应原因，避免成功样式。

验收标准：本例显示“工况不符，不能判断 200°C 目标是否达成”；排除后不再显示达标字样。

### A03 · P1 · 已复现错误：115% 的成分可以入库

步骤：候选登记输入 `Al 90 / Cu 20 / Mg 5`，配比基准 wt%，点击保存。

实际：直接保存为 C-1e52545f，无总量检查或无效状态提示。成分目前是一个文本框，配比基准虽可选，但没有元素级数值结构。

修改：元素、数值/范围、wt%/at%、余量元素结构化；校验合法元素、重复元素、负数、总量、余量和范围。不能解析时允许作为待整理原文保存，但禁止作为可执行候选。

验收标准：115% 被明确拒绝或标记为不可执行，用户能定位具体错误并修订；修改有版本记录。

### A04 · P1 · 能力缺口：对话不能承担研究规划，记忆不等于综合推理

实测一：首次对话请求“建立 AUD-906、澄清缺失条件、选择仿真和实验”，回复仅摘录 CALPHAD 工具说明，没有澄清、项目草稿或可执行下一步。随后手动新建研究，表单没有带入已有需求。

实测二：新会话询问“目标工况、强度目标、最新结果是否达标”，回复只有样品工艺与 200°C 备注，没有回答强度目标和最新结果。

正向结果：退出再登录后，询问精确代号 `AUD-QUEUE`，能找到此前在工具页保存的 DFT 接入需求。页面诚实标注本地检索、未接入大模型。

修改：保留检索与来源机制，增加问题拆解、结构化项目查询、跨来源归纳和有权限的操作草稿。规划类请求应得到待确认计划；事实问题应覆盖所问各项，找不到就明确说明，不用单条相关摘录代替答案。

### A05 · P1 · 能力缺口：仿真与实验协同停在任务名称和接入说明

实际：选择 DFT/CFD 后生成通用任务，样品制备固定等待 CALPHAD、DFT、CFD；无法在页面定义具体输入工件、输出字段、版本、数据转换、责任人、排期和验收条件。DFT 配置弹窗只有接入方式、说明；保存后仍显示待接通，这个状态提示正确。

实验室只有三类设备接入位，不能预约设备、关联具体执行者、派发任务或回收原始曲线/图像。成员页只能保存邀请草稿，不能完成真实多人协作。

修改：将每项任务定义为输入、输出、方法/版本、资源、责任人、时限、成本与质量门槛；依研究问题设置必要/可选/并行依赖。先打通一个实际计算适配器与一条人工实验回传通道，再逐步增加设备自动控制。

验收标准：某个候选的计算输出可以作为有版本的下游输入；任务能提交、失败、重试、取消并回收结果。人工实验也能指定负责人，归档原始文件后进入质量复核。

### A06 · P1 · 能力缺口：下一轮还不是可执行的实验设计

实际：第二次虚构结果为 285 MPa / 7.6%，复核后可生成“2 个复测样 + 1 个工艺对照样 + 1 个参考样”。没有指定候选、参考材料、改变的工艺变量及取值、各测试工况与重复分配。确认后显示计划已归档、等待资源，仍为第 1 轮、1 个样品，没有形成新的轮次任务与样品清单。

修改：下一轮草案要包含候选 ID、具体变量、对照/重复、验证假设、成本与停止条件。确认后形成新的轮次计划与待执行对象，同时保留上一轮原始证据及版本。

验收标准：计划中的每一个样品都能追踪到候选和工艺变化，能分配执行，而不是确认一段文字后结束。

### A07 · P1 · 数据模型缺口：实验记录不足以支持多材料、多指标比较

实际：结果表单固定屈服强度和延伸率；温度、标准、尺寸、应变速率、重复次数只能写进自由文本。新录入成为当前结果；旧录入有历史但没有按候选/批次/工况汇总比较。未提供原始曲线解析、不确定性或重复样本统计。

另外，仅录入结果便把“室温拉伸测试”改为已完成，但上游制备仍待执行、样品仍已登记。导入已有实验当然应允许，然而“已导入历史结果”与“本平台执行完成”不应混为同一状态。

修改：建立候选—批次—样品—试样—测量的关联；指标可扩展且带单位与条件。原始文件和派生数据分开，记录来源/版本/复核。任务执行状态与结果录入状态分别表示；对照、重复和排除规则形成可比较的数据集。

### A08 · P2 · 实测质量问题：题录采集缺少文献类型与材料相关性筛选

查询：`Al Cu Mg alloy elevated temperature tensile properties`，Crossref 5 条。

实际：返回 2 条标题为 `Review for ...`、DOI 以 `/v1/review1` 与 `/v2/review1` 结尾的审稿记录，另有 Mg-3%Al 体系论文。全部显示为普通“文献”，没有区分审稿意见与原论文。界面报告来源匹配 5,364,239 条，但没有解释相关性或给出类型过滤。新采集框还默认填入与当前铝合金项目不符的 `nickel based superalloy`。

修改：采集前显示由项目目标生成的可编辑检索式；增加材料体系、文献类型、年份、测试工况筛选，保存来源类型和版本关系。将低相关结果标记为候选资料，待筛选后进入研究证据范围。条目数量不等于有效证据覆盖。

### A09 · P2 · 产品作用范围不统一

实际：「账号与用量」中隐私与模型修改的是左侧当前项目；余额、成员与自动记忆面向账号/空间。页面文字说明了项目范围，但同一设置区混用两种作用域。新用户首次进入对话却显示“从上一次研究继续”“今天继续哪一项研究”。

修改：账号设置放默认隐私、默认模型、成员、余额；项目设置放覆盖项，常驻显示作用范围。新账号显示“开始第一项研究”，已有账号显示最近项目与待处理事项。不要让侧栏项目选择在用户未注意时改变账号页的操作对象。

### A10 · P2 · 页面动作和纠错路径需要补齐

- 「保存并进入复核」两次都只保存并停在实验页，需自己找到结果/复核入口；应按按钮承诺跳转或直接打开复核。
- 候选和样品登记没有看到编辑入口；成分输错后缺少直接修正和版本差异查看。
- 样品关联候选下拉只显示 `C-xxxxxxxx`，默认第一个甚至可能是无效候选；应显示成分、工艺和有效状态，并要求明确选择。
- 工作流列表中缺资源的任务仍统一写待执行；应直接写“缺执行资源”“待输入校验”“待负责人确认”，并给出解决入口。
- 保持现有中性色，优先用文字、图标、字重与位置区分已完成、待处理、阻塞、排除。无需增加鲜艳配色或更大的装饰卡片。

## 建议开发顺序

1. **正确性先行**：修 A01/A02/A03，同时把实验条件与质量状态结构化。用本轮负向样例作为回归验收。
2. **完成一个窄范围闭环**：选一个明确合金应用，把目标 → 候选 → 一项真实计算 → 人工实验回传 → 质量门槛 → 下一轮样品清单接通；补齐 A05/A06/A07。
3. **让助手组织工作**：对话承接需求、生成可确认操作、综合读取当前有效证据，补齐 A04，而非仅扩大记忆条目数。
4. **完善团队与体验**：作用范围、真实成员、负责人/时间、检索筛选和纠错入口；继续沿用现有中性色视觉。

是否部署仍由用户验收决定；当前建议先解决前三项正确性问题，再进行下一轮研发验收。
